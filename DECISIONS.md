# Decisions

Each entry: the decision, why, what it rules out, date. A later entry supersedes an earlier one by number.

**D-01 · The local service is C++ and serves both the app and the store.** (2026-10-17)
The specification forbids a Node.js runtime dependency and requires SQLite. A C++ process that serves
`app/` statically and exposes the model API on localhost satisfies both with one binary; SQLite is
linked (system library here; amalgamation on Windows, A-05). Rules out: SQLite-in-WASM in the browser
(no Emscripten in this environment; would duplicate the store), a Node dev server as the product.

**D-02 · Node and Playwright are development tools only.** (2026-10-17)
Unit tests run under `node --test`; the end-to-end slice drives headless Chromium through Playwright.
Nothing under `app/` or `service/` needs them. stiffness already uses node this way (`tools/serve.mjs`,
`tests/wasm-gate.mjs`). Rules out: a bespoke test runner in C++ for JavaScript.

**D-03 · Reuse across repositories is by verbatim vendoring with a provenance header.** (2026-10-17)
`service/json.h` is stiffness `src/json.h` at commit d836c1f with two header lines added. No submodule:
stiffness is private, and a reader of this repo must be able to build it alone. The rule: fix upstream,
re-vendor, never fork silently. Rules out: a second JSON implementation.

**D-04 · drewbt/stiffness is the structural engine; this repo does not re-implement analysis.** (2026-10-17)
Discovery found no code in `coraljs`; the working Coral engine is `stiffness` (sparse LDLᵀ, beams,
shells, sections, CBFEM, 40-check gate, builds on Linux with CMake, all pass). Milestone 2 calls it
(CLI or C ABI/WASM) on the model's structural projection. Rules out: writing a solver here.

**D-05 · Parameter values travel and are stored as JSON text, never re-serialised by the service.** (2026-10-17)
So the canonical model text, and therefore the model hash, is byte-identical in JavaScript and C++
(gated: unit hash.test.mjs vs service-gate, and the e2e history check on a real model). Rules out:
parsing numbers in the service (json.h writes 17 digits; JS writes shortest round-trip).

**D-06 · A trace is a record; a component is derived from it.** (2026-10-17)
Trace elements hold the clicked pixels; components hold metres and name their trace in provenance.
`Re-derive` propagates a calibration correction. Rules out: storing only metres (loses the measurement)
or only pixels (engineering never sees pixels).

**D-07 · The drawing's calibration stores the measurement, not the scale.** (2026-10-17)
`cal_p1`, `cal_p2`, `cal_distance` are the parameters; `trace.pixelToWorld@2.0.0` derives the scale.
Supersedes the 1.0.0 form that stored `scale` directly (changed before any data was persisted).

**D-08 · Engineering meshes are doubles; the renderer downcasts.** (2026-10-17)
The divergence-theorem volume gate at 1e-9 m³ fails on Float32 vertices (seen at 5e-8). Rules out:
sharing one Float32 buffer between engineering and rendering.

**D-09 · The properties panel patches in place and serialises its renders.** (2026-10-17)
Replacing the DOM under a focused input fires its change event inside the render and the outer render
then overwrites the result (seen in e2e). Rules out: naive full re-render on every model event.

**D-10 · Work is committed to a branch and pushed from this session; no pull request is opened.** (2026-10-17)
The session container is ephemeral. Pushing preserves the green baseline; the PR is the owner's call.

**D-11 · The structural engine runs as a separate process, never vendored.** (2026-10-17)
drewbt/stiffness is private and this repository is public. The service runs its `stiffness` CLI as a
subprocess (`--engine path`) and records the binary's SHA-256 with every result. The results cache key
is the SHA-256 of the exact model text plus the engine's hash: the same text through the same binary is
the same answer. Rules out: copying engine source here, a second solver.

**D-12 · ACI 318-19 is the first design ruleset.** (2026-10-17)
The public-record project, Fallingwater, is in Pennsylvania. The ruleset is data with a clause per value
(app/core/standards/aci318-19.js) and is marked unverified until checked against the printed code.

**D-13 · Bars are model elements with a design basis hash.** (2026-10-17)
Each bar is a `rebar` element under its beam, carrying the SHA-256 of every input and function version
its design read (`basis`). When the beam changes the basis changes, the bars read "stale", and they are
regenerated by a person's action, not silently. Deleting a beam deletes its bars.

**D-14 · Bulk changes are batches: one listener event and one undo step.** (2026-10-17)
A detailed slab adds ~1,500 bars; per-element events re-rendered the tree each time. `model.batch(label,
fn)` keeps every element's own event in the log but notifies once and undoes as one step. The dependency
graph's reverse index is rebuilt only after a structural change.

**D-15 · A check superseded by a more appropriate method stays visible but does not govern.** (2026-10-17)
Sectional shear rows of a deep cap designed by strut-and-tie, and the unreinforced punching row of a column
given stud rails, carry `superseded` with the reason. Rules out: deleting rows, or letting a wrong model
decide adequacy.

**D-16 · Foundations are chosen by search, not by a single guess.** (2026-10-17)
Pile diameter (with its assumed allowable) × cap depth, cheapest first, keeping the first arrangement whose
governing check passes, including grade-beam reactions that land on the cap. The best failing arrangement is
kept and reported when none passes.

**D-17 · One function decides bar positions for both the check and the drawing.** (2026-10-17)
`stripPositions` lays column-strip bars symmetrically about the column line; the integrity check (8.7.4.2.1)
and the bar generator call it, so the check cannot describe bars that are not drawn.

**D-18 · A published static copy answers the API in the browser.** (2026-10-19)
`core/api-local.js` keeps the model in browser storage and answers analyses only from engine results captured
by `tools/build-static.mjs` from real runs, keyed as the service keys them. Any other analysis is refused
with a message. No engine code ships; the published page opens on the designed reference frame.

**D-19 · The model comes first.** (2026-10-19)
The user reported the staged interface did not work for them and that the model takes priority. Page 02 is now
"Model" and fills the window: view toggles (X-ray, ghost slabs, bars, punching zones, cut), colour by governing
utilisation (default) or material, an Add menu, and a Design drawer that holds the former page 03. Routes
`#architecture` and `#structure` redirect to `#model` (the latter opens the drawer). The event log is collapsed
to one status line. Slabs open ghosted so columns, caps and piles show their colours. Utilisation colours come
from the same design results as the tables; an undesigned element is drawn by material.

**D-20 · The ground is part of the model.** (2026-10-20)
A `soil` element (surface, water table, factor of safety, plan extent) with `soil_layer` children is the one
source for pile capacity and for the earth drawn in the Model view. Pile length is designed, not assumed:
the foundation search runs over pile diameter × count × cap depth for the least concrete, each pile as short
as the profile allows. The earth is drawn as a cutaway (inner faces only) so the piles stay visible; it is
never picked, never fitted and never counted as concrete. Browser storage of the published copy is keyed by
its seed so a rebuilt copy is not masked by an older saved model.

**D-21 · A tower is modelled floor by floor; member design is refused for it, not approximated.** (2026-10-20)
`core/tower.js` generates a synthetic needle tower (every storey: slab, east and west walls, core, columns or a
facade tube, cellars, mat on rock, Central Park as context). The one-storey design path (DDM slabs, column
takedown, pile caps) is refused for a model with walls or columns on more than one level; the drawer shows the
gravity summary and the wind and vibration analysis instead.

**D-22 · Wind and vibration: the engine for dynamics, ASCE 7-16 for loads, and the wind tunnel named as the
code route.** (2026-10-20)
The tower's lateral system is read from its own walls into a wide-column frame (`core/towerdyn.js`) and run in
the stiffness engine for modes, then for wind at the ultimate and 10-year speeds with ASCE 7-16 flexible gust
factors computed from those modes. Along-wind acceleration per C26.11; across-wind by the NBCC Commentary I
expression, marked indicative outside its range. ASCE 7-16 27.1.3 sends a building governed by across-wind
response to Chapter 31: no analytical result is called compliance. Coral's LBM wind tunnel (SvgCAD
`physics.js`) is not in any reachable repository; its C++ port remains owed (stiffness GAPS.md).
The form and system are chosen by `tools/optimise-tower.mjs`, a search whose every candidate runs the engine;
its record is `docs/tower-wind.json`.

**D-23 · Comfort first: the tower is the tallest form whose sway is comfortable.** (2026-10-20)
The owner's brief: occupants must be comfortable and the design must not invite claims. Design target 10 milli-g
peak acceleration under the 10-year wind, along- and across-wind, the low end of the residential range and two
thirds of the 15 milli-g criterion; the margin covers the across-wind screen being outside its calibration.
`tools/optimise-comfort.mjs` ran 144 full towers through the engine (height 297-435 m, width 20-32 m, taper,
damper 1600-4800 t). No 84-storey (435 m) form reaches 10 milli-g (best 13.3); the tallest that does is 74
storeys, 389 m, 32 m wide (12:1), facade tube, four outriggers, 3200 t damper: 9.7 milli-g
(docs/tower-comfort.json). That is now the default tower; docs/tower-wind.json keeps the earlier
least-concrete 435 m search, which met the code route but not comfort. The tunnel test remains the confirmation.

**D-24 · Architecture over the structure, and a presentation render.** (2026-10-20)
Direction from the owner: the tower read as a solid block; take marketing-grade visualisation (Emaar's launches:
blue-hour skies, silvered glass with vertical fins, floors lit from within, a lit crown and spire, low views
across water or park with the city in haze) as the visual brief. The facade is modelled, not painted: a
`curtain_wall` element per storey (vision glass over spandrels, fins at 1.5 m, louvred mechanical floors, a
full-height lobby, a glowing crown lantern) and a `spire`, each with provenance; the facade's 0.5 kPa weight goes
into gravity and the dynamic model (comfort rechecked: 9.73 milli-g). The city and park trees are illustrative
massing, labelled so. The viewer gains a Render mode (analytic dusk sky warm only towards the sun, Fresnel glass
reflecting it over procedurally lit rooms, brushed fins, haze) that hides analysis overlays and frames a hero
view from the park; Engineering mode is unchanged, with the facade as faint glass. Emaar's own pages were not
reachable from the build environment, so the brief is their established, published visual language rather than
a specific brochure.

**D-25 · An actual site, real neighbours, an organic form from precedent.** (2026-10-20)
Brief: a more organic form on an actual site among its actual surroundings. Site: the Park Lane Hotel footprint,
36 Central Park South, a documented supertall site (Witkoff's "1 Park Lane", reported on hold); this is a design
study, not the owner's scheme. Surroundings: every building within 650 m from OpenStreetMap (the NYC building
import, extract of 2015-12-30, found in a public repository because NYC Open Data and Overpass were blocked by the
environment's network policy), plus Central Park Tower, 111 W 57th, 220 CPS and 53 W 53rd added from published
heights at approximate positions. Form, after Shanghai Tower, Lakhta Center and Jeddah Tower: a superellipse
plate that tapers and turns with height (a quarter turn to 62 %), round a straight core, with a concrete tube on
the largest rectangle each plate contains, so the engine frame still applies; the generator refuses any plate
that leaves the lot or cannot hold the tube. The lot set the plate (28.5 × 24.4 m); comfort then set the
height: `tools/optimise-site.mjs` ran 240 towers, 80 refused by the lot; the tallest comfortable form whose
across-wind estimate is inside its method's range is 52 storeys, 285 m. The search's cheapest at that height
turns 45°; the 90° turn is kept for the brief at 1 % more concrete. Penthouses and an open crown at the top
(D-26).

**D-26 · Penthouses and an open crown; every storey screened.** (2026-10-20)
The owner asked for a top flourish for penthouses that does little for wind. The top three storeys are
double-height with the glass line set back about 2 m (wrap-around terraces, glass balustrades), so the wind sees
the smaller enclosure; above the roof an open crown of blades leans in and turns, lit at the tips, with no tube:
only the core rises through it. Its wind area is the blade solidity (about 0.2), not the outline. Adding the
crown exposed two gaps that are now closed: pier stresses are screened at every storey, not only the base, and
the 1.4.3 notional load runs as its own engine case.
